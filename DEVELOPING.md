# Developing

Everything the README deliberately leaves out: building, testing, and how the
engine works internally. None of this is needed to *use* the spoofer on an
iPhone — GitHub Actions renders the modules automatically.

## Commands

```sh
node tools/cli.mjs build all [lat] [lng] [hacc]   # render all module files into dist/
node tools/cli.mjs test                           # engine unit tests (46)
node tools/cli.mjs demo                           # end-to-end fixture run
node tools/cli.mjs dump <hexfile>                 # patch a captured hex dump
node test/runtime.test.mjs                        # proxy-app sandbox tests (17)
node test/picker.test.mjs                         # Node picker handler tests (10)
node test/worker.test.mjs                         # Cloudflare Worker tests (14)
node tools/build-dist.mjs                         # dist/wloc.engine.js only
node tools/make-fixture.mjs                       # regenerate test/fixtures/arpc-response.hex
```

No dependencies; Node 18+ for the dev tools, iOS 12-compatible output for the
engine itself.

## Project layout

```
core/wloc.mjs            engine: framing, protobuf, patching (ES module)
core/runtime.js          proxy-app adapter ($request/$response/$done mapping)
modules/*.template       module templates with {{REPO}}/{{BRANCH}}/{{LATITUDE}} placeholders
tools/build-dist.mjs     engine+adapter -> dist/wloc.engine.js
tools/cli.mjs            build / test / demo / dump
tools/make-fixture.mjs   regenerate test/fixtures/arpc-response.hex
test/wloc.test.mjs       engine unit + integration tests
test/runtime.test.mjs    sandbox tests: SR bytes, Loon/QX base64, cron, config
test/picker.test.mjs     Node picker: token gate, loc.json, /set, /search
test/worker.test.mjs     Worker: same contract on mock KV, no Miniflare
location-picker/server.mjs  self-hosted picker (Node, no deps)
location-picker/worker.js   Cloudflare Worker picker (same API, KV-backed)
dist/                    generated modules + engine (committed; modules fetch it from GitHub)
```

## CI

`.github/workflows/ci.yml` runs all four test suites, renders `dist/` with
`MYROCKET_LAT`/`MYROCKET_LNG`/`MYROCKET_HACC` repository variables (settable
from the GitHub mobile app), and commits the result on the default branch.
Pushing a `v*` tag runs the release workflow, attaching modules with pinned,
immutable `script-path` URLs.

## Remote config contract

Both picker backends serve the same contract the engine consumes via the
module's `configUrl` argument:

- `GET /loc.json?token=T` → `{"latitude":number,"longitude":number,
  "horizontalAccuracy":number,"updatedAt":"ISO-8601"}` — the engine refreshes
  this inline before each patch and prefers it over hardcoded arguments;
  on failure it falls back to the last cached value, then to the arguments.
- `POST /set?token=T` with the same JSON body (without `updatedAt`) updates
  the target; input is validated to WGS-84 bounds.
- `GET /stats?token=T` → badge data (`fetchCount`, `lastFetchAt`).
- `GET /health` → `{"ok":true}`, no token, for uptime checks.
- `GET /search?token=T&q=address` → `[{label,latitude,longitude}]` from
  Nominatim (Node and Worker backends alike).

The engine-side fetch/cache logic lives in `core/runtime.js`
(`resolveConfigUrl`, `cacheRemoteConfig`, cron support for Loon).

## Response framing support

The engine tries, in order:

1. **ARPC envelope** — real Apple responses (version + pascal strings +
   function id + payload); re-serialized in place after patching.
2. **Synthetic framing** — responses previously produced by this engine
   (8-byte prefix + uint16 length), so re-patching is idempotent.
3. **Marker framing** — `00 00 00 01 00 00` + uint16 length with preserved
   surrounding bytes.
4. **Bare protobuf** — a naked AppleWLoc message.
5. **Raw byte scan** — none of the above matched: slide over the buffer and
   patch the first offset that parses as a patchable AppleWLoc message,
   re-framed as a synthetic response. This is the safety net when Apple
   changes envelope details in a beta.

If nothing patches, the original response is passed through (fail-open), so a
format change degrades to "real location" instead of "no location".

Only latitude (field 1), longitude (field 2), and horizontal accuracy
(field 3) are replaced, and only inside `Location` submessages under the
Wi-Fi (field 2) and cell-tower (fields 22/24) roots. Altitude, motion state,
and every unknown field pass through byte-for-byte.

## iOS 12 compatibility

`dist/wloc.engine.js` is generated by `tools/build-dist.mjs`: engine
(`core/wloc.mjs`) plus host adapter (`core/runtime.js`) concatenated and
export-stripped. It must parse on iOS 12 JavaScriptCore: no BigInt, no
optional chaining, 64-bit varints handled as 32-bit pairs. The sandbox tests
verify the generated bundle stays within that dialect.
